# API Parity Audit: libavoid-rust vs libavoid-js

**Date:** 2025-11-23 17:51
**Objective:** MECE gap analysis for 100% API compatibility

---

## Executive Summary

| Category | libavoid-js | libavoid-rust | Parity | Priority |
|----------|-------------|---------------|--------|----------|
| Core Functionality | Complete | Partial | ~70% | HIGH |
| WASM/JS Bindings | 15 classes | 7 classes | ~45% | CRITICAL |
| Test Coverage | Examples only | 43 tests | N/A | LOW |

**Critical Finding:** The WASM bindings in libavoid-rust expose only ~45% of the API surface required for drop-in compatibility with libavoid-js. While the core Rust library has most functionality implemented, the JavaScript-facing API is severely underexposed.

### 2.4 Method Signature Discrepancies

**Router:**
```javascript
// libavoid-js
new Avoid.Router(Avoid.PolyLineRouting)  // number
router.moveShape(shapeRef, newPolygon)   // with Polygon
router.moveShape(shapeRef, xDiff, yDiff) // with offsets

// libavoid-rust WASM
new Router(RoutingType.PolyLineRouting)  // enum (different API!)
router.moveShape(shapeRef, x, y)         // only offset version
```

**ConnRef:**
```javascript
// libavoid-js
new Avoid.ConnRef(router, srcConnEnd, dstConnEnd, optionalId)
connRef.setCallback(callback, connRef)  // callback receives raw pointer

// libavoid-rust WASM
new ConnRef(router)  // only basic constructor
connRef.setCallback(callback, context)  // stub, not functional
```
